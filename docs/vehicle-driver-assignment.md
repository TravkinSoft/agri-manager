# Постоянный водитель машины

Одна привязка для справочника автопарка, весовой и страницы оборота машин.
Быстрый редактор: выбрать действующего водителя компании или «Без водителя», сохранить.
Назначение действует до следующей ручной смены. Другие машины того же водителя автоматически не отвязываются.

## Данные и права

- Канонический сотрудник: `company_people`, role_type=driver, active, not deleted.
- Существующее поле машины `reference_vehicles.primary_responsible_personnel_id` сохраняется.
  Оно ссылается на `reference_specialists`, который связан с человеком по точному `person_id`.
  При первом назначении создаётся только недостающая совместимая ссылка — не новый человек.
  Уникальный индекс защищает от двойного создания; совпадение имён не используется для связывания.
- Общий GET/POST `/api/vehicles/driver-assignment`: свежая роль/компания, same-origin POST,
  проверка актуального значения перед записью, подтверждение затронутой строки.
- Менять: администратор, агроном, весовщик. Для весовщика требуется действующая PIN-смена.
  Рабочие PTC видят водителя, но не получают управление общим автопарком.
- При конфликте показывается текущее назначение, затем пользователь подтверждает новый выбор.
- Никаких изменений существующих талонов, весов, остатков или PTC-состояний/событий.
  Явное сохранение из новой несохранённой формы весовой может обновить её выбранного водителя;
  уже созданный талон не меняется. Постоянная привязка приоритетнее исторических подсказок.

## Интерфейс и актуальность

- Справочник: колонка «Водитель» в автопарке.
- Оборот машин агронома: значок водителя 48x48 на компактной карточке. У работников — только имя.
- Весовая: тот же редактор рядом с выбранной машиной.
- Списки запрашиваются только при открытии редактора, не по запросу на каждую карточку.
- Подтверждённый результат обновляет локальные экраны и соседние вкладки через общий event/BroadcastChannel.
  На возврате в справочник данные перечитываются; PTC сохраняет свой регулярный опрос.
- Имена/активность текущего водителя берутся из канонической карточки сотрудника, не из старой копии.
- Мобильные цели48px, поиск16px, ширина окна и выпадающего списка ограничены экраном.

## Проверки и выпуск

Точечные проверки: `qa-vehicle-driver-api.ts`, `qa-vehicle-driver-picker.ts`,
`qa-vehicle-driver-weighbridge.ts`, `qa-vehicle-driver-surfaces.ts`, регрессия PTC и TypeScript/lint.
Затем браузерная QA-проверка назначения/смены/снятия с существующими сотрудниками и машиной;
старые события/талоны сохраняются. Product проверяется без назначения водителя за владельца.
Схема БД не меняется. Выпуск — отдельная Production-сборка основной ветки, не перенос QA-артефакта.
Откат интерфейса/кода не должен удалять сохранённые привязки, людей или историю.
