## Граница данных

Реальная база — только чтение, включая отсутствие миграций, исправлений исторических талонов, смен/PIN и импорта бумажных рейсов. Проверки создания, закрытия, аннулирования и повторов — локально на вымышленных данных. Деплой кода разрешён владельцем. Пока идёт обслуживание, закрывается только весовая и запись через её API. Склады и другие разделы доступны.

## План и критерии приёмки

1. Сервисное сообщение и честный таймер; только весовая; данные не меняются.
2. Выбор одной/нескольких партий, обычный приход, последовательные талоны, смена водителя/веса/склада, восстановление черновика, обновления и медленная сеть. Выбор не сбрасывается, чужой черновик не подменяет текущий.
3. Брутто/тара/нетто: явный ввод, строгая проверка, снимок отправляемых значений, округление, несовместимый повтор, изменение открытого талона. Фон не подставляет и не переписывает вес.
4. Создание/закрытие/аннулирование/исправление: атомарность, один результат на повтор, конкурентность, потерянный ответ, откат ошибки, освобождение машины и неизменность закрытого документа.
5. Земля/общая примесь: отдельные исходные партии, без придуманного распределения общего веса, корректный общий вычет, последующие талоны, остаток и история.
6. Склады: сверка движений, аннулирований, остатка, происхождения, сезон/склад/компания. Только чтение реальных данных; различать историческое расхождение и текущую ошибку кода.
7. Доступ: анонимный пользователь, другая компания, роли, смена и оператор; фоновые записи и устаревшие страницы.
8. Скорость: ограниченный объём чтения, отсутствие циклов и повторных тяжёлых запросов, дедупликация, предельное ожидание, понятное восстановление.
9. Полный прогон доступных локальных регрессий, проверка браузером, сборка, выпуск, повторная проверка живой версии, снятие обслуживания.

Каждый пункт отчёта должен иметь результат, доказательство и непроверенную границу. Отсутствие ошибки в журнале не равно доказательству исправности. Нельзя обещать отсутствие любых будущих ошибок.

## Найдено и исправлено

1. После создания первого талона примеси форма сохраняла уже занятой источник. После обновления остатков старый источник исчезал, но продолжал блокировать все новые варианты. Теперь использованный выбор очищается, а исчезнувшие источники не блокируют следующий рейс.
2. Повторный клик и переключение рабочей вкладки могли пересечься с отправкой талона. Добавлена мгновенная блокировка повторной отправки и переключения вкладок до завершения запроса.
3. Значение брутто могло читаться через обычное преобразование строки. Все весовые значения теперь проходят одну строгую проверку; фоновые данные не могут подменить текущий ручной ввод.
4. Изменение веса открытого талона не во всех режимах проходило через единое атомарное обновление. Теперь исключение оставлено только для явно оформленного ручного исправления с причиной.
5. Живое изменение из базы могло ждать общий десятисекундный ограничитель фоновых обновлений. Для фактического изменения талона, машины или остатка задержка снята; обычный фоновый опрос остаётся редким, чтобы не перегружать страницу.
6. Сервисное окно было слишком широко применено к соседним страницам. Теперь закрывается только точный адрес `/weighbridge`; «Оборот машин» остаётся доступным.
