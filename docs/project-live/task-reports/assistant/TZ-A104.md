## Result

The panel now sends only the new message, thread ID, current page/module/season, selected UI IDs, and authenticated company context. It does not send conversation history, history scope, session memory, or thread state. The route validates the thread and company, stores the user message, reloads the server transcript, filters it, reconstructs structured focus, then calls one explicit runtime adapter.

The Responses adapter supports developer/system instructions, ordered conversation input, exact function schemas, function calls, `function_call_output` results, final text, usage, cached input tokens, latency, request ID, effective model, and explicit error payloads. Legacy Chat Completions remains a separate physical adapter and the production default. No fallback crosses the two adapters.

History loading was corrected from oldest rows to newest rows returned chronologically. Empty, system, tool, debug, technical, internal, client-hint, injection-like, and secret-like messages are excluded. The current user row is excluded from replay and appended exactly once as current input. `history_truncated` is recorded. A nullable versioned summary slot prepares the metadata contract for A105 without generating summaries now.

UI object IDs are untrusted until a user-JWT/RLS read verifies UUID, row, and company. Labels are server-derived. Current tool output may advance focus and records the last successful allowlisted tool. Cross-thread metadata is discarded.

## State decision

Real OpenAI comparison proved that `previous_response_id` restores provider context and rejects a bad ID explicitly. The main runtime nevertheless uses `store:false` and Supabase replay because it provides one auditable thread/user/company source of truth, deterministic reload/device continuity, deletion control, and rollback without provider cursor expiry or a second state store. Previous-response input is still billable and instructions must be supplied per request.

## Errors and durability

Model-not-found, invalid/expired state, timeout, rate limit, network, parse, tool policy/result, user persistence, and assistant persistence paths are explicit. A model/runtime failure leaves the already-required user row but returns `memorySaved:false` and does not write an assistant answer. An assistant-row failure returns 500 and cannot claim success. Thread-title refresh is non-critical only after the assistant row is durable.
