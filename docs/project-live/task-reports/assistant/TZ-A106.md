## Repeated greeting correction

The server previously classified greetings and disabled tools correctly, but it did not tell the model whether the current response was the first response in the persisted thread. QUESTION, DATA, and follow-up generations therefore remained free to start with another greeting. Preferred-address memory increased the visible repetition because the model often emitted the address together with that greeting.

The corrected server-owned greeting policy derives its decision from persisted meaningful message count and the current user text. A greeting is allowed for the first response of a new thread or when the current user message is an explicit greeting. Otherwise the prompt requires a direct answer with no repeated greeting and asks the model to use the preferred form of address naturally rather than in every response. A deterministic final-answer guard removes any leading Russian or English greeting that still escapes the model, including an address-plus-greeting prefix. The decision and whether a greeting was removed are persisted in assistant message metadata and returned in safe response metadata.
