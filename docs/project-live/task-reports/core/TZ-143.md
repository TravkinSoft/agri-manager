## Result

Проблема подтверждена. Нормальный warehouse posting и его TypeScript fallback используют `base_quantity_kg ?? quantity` и жёстко записывают ledger `uom=kg`. Возврат материалов не переносит unit в `inventory_transactions`. Material issue и weighbridge используют `kg`/`commodity` fallbacks. Balance views суммируют количества без `uom`; identity view маскирует `batch_class=NULL` как `commodity`.

Выбран Variant B: additive universal model `base_quantity + base_uom`, optional `mass_kg`, optional verified density with source. Legacy `base_quantity_kg` сохраняется только как compatibility mass field на время staged cutover. `material` должен стать допустимым canonical batch class. Writer обязан остановиться при отсутствующей/противоречивой metadata.

## Audit facts

- Writer scenarios reviewed: 18.
- Direct unit bug/risk: 15; storno inherits source; harvest and weight-only processing are intrinsically kg.
- Direct batch-class bug/risk: 15; storno inherits source; harvest/processing resolve class explicitly.
- Legacy confirmed inventory rows: 7.
- Corresponding ledger rows: 7.
- Liter rows: 5 (`80`, `30`, `5`, `2`, `0.2`).
- Kg rows: 2 (`12000`, `5000`).
- Seed rows: 1.
- Canonical quantity/uom is provable for all 7 rows.
- `mass_kg` is unprovable for 5 liter rows; exact batch ID is unprovable for all 7 rows and must not be invented.
- No verified density exists for the affected liquids.

## Current schema decision

NEW_SCHEMA_REQUIRED: YES, additive only.

Required direction:

- transaction: universal quantity/uom, optional mass/density provenance, explicit class;
- ledger: exact quantity/uom/class and optional mass snapshot;
- batch: universal initial/current quantity and uom, legacy weight fields retained during cutover;
- views: group/reconcile by uom and do not coalesce missing class to commodity;
- writer resolver: product/event metadata is authoritative; no client/default kg/commodity fallback.
