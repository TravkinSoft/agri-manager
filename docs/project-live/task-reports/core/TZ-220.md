# TZ-220 - Specialist task workspace and full work plan

Date: 2026-07-24

Branch: `copilot-v1`

Status: `DONE_WITH_SCREENSHOT_CAPTURE_GAP`

## Result

The Specialist workspace now follows the approved master-detail layout:

- desktop keeps a compact task list beside one full selected plan;
- mobile uses the compact list and a full-screen task detail;
- New, In progress and Completed are separate status tabs;
- the selected task is highlighted without changing its business state;
- a New task is read-only and exposes only Accept;
- Accept opens a confirmation with work, field, area and date, then moves the
  task directly to In progress without a separate Start command.

The full plan uses the shared operation presentation model from TZ-218. It
shows the concrete work title, crop identity, all plots, immutable plan,
responsible person, machinery, equipment, agronomist comment and only
non-empty type-specific sections. Materials are read-only. Warehouse
accounting fields such as consumed, returned and loss are not editable here.

Spraying presents the calculation in agronomic order: solution rate,
materials and formulas, liquid-material total, system-calculated water,
concentration, and final ready solution last. Water is not presented as a
material. Soil, sowing, fertilizer, irrigation and harvest cards use their
relevant plan fields without generic empty blocks. A map was intentionally not
implemented in this scope.

## Progress and completion

The shift form stores a delta against cumulative progress. Before submission
it shows the resulting total and remaining area or over-plan deviation.
Under-plan submission requires a stop reason. Over-plan submission requires a
deviation reason. Submission has a final confirmation and cancellation
returns to the unchanged form. Finish includes the current shift in the final
calculation. Completed tasks show plan, fact and deviation and do not show a
remaining-work field.

No acceptance, progress or completion confirmation was executed during the
final browser smoke, so no ERP operation data was written.

## Schema alignment fixes

Authenticated Preview smoke exposed two stale read contracts:

- `operation_materials.rate_basis` was queried as a physical column although
  the canonical value is encoded in `notes`;
- non-existent operation columns were selected instead of reading the
  canonical `operation_config`.

Both reads now use the production-equivalent schema. QA fixtures are visible
only inside an explicitly QA-named company, preserving the production QA
filter for ordinary companies.
