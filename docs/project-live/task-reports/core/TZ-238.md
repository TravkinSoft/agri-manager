## Result

Warehouse preparation and issue now preserve the agronomist plan while allowing
an explicitly selected whole package to exceed that plan. The selected batch,
package size, package count and issue mode are stored per request-item
allocation. Prepared and issued quantities can exceed the plan, but never the
available stock.

The Specialist task shows stable operation and field numbers, human operation
labels, crop identity, warehouse request status, prepared/issued quantities,
package details and expected return. Completed tasks are read-only.

Exact QA test markers hide E2E clutter by default. Three unambiguous
`E2E-TZ235` fields were archived without deleting operations, requests,
tickets, batches, ledger or field history.

## Root Causes

- One request item could not represent multiple explicitly selected batches or
  batch-specific package sizes.
- Issue could rebuild a FIFO allocation instead of using the warehousekeeper's
  confirmed preparation.
- Plan, preparation, issue and actual consumption were presented as one
  quantity, so whole-package over-plan issue looked like an error.
- Specialist cards lacked stable operation/field identifiers and material
  handoff facts.
- E2E records had no exact root marker or opt-in visibility control.

## Package Contract

- Package source priority: selected batch, then product fallback, then manual
  package size with a required reason.
- Modes: `whole_package` and `measured`.
- Whole-package count is an integer and preparation is
  `package_count * package_size`.
- Multiple explicit allocations are summed; silent cross-batch FIFO selection
  is not used.
- Ready reserves the prepared quantity.
- Issue writes one allocation-bound ledger OUT per selected allocation.
- Expected return is informational until the physical return is accepted.
- Final reconciliation enforces:
  `issued = consumed + returned + loss`.
