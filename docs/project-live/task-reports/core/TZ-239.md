## Result

Warehouse preparation and issue now use one direct material quantity. The
warehousekeeper no longer selects package size, package count, whole-package
mode, measured mode or a manual package reason.

The warehouse request table contains exactly six business columns:

1. Material
2. Planned requirement
3. Available
4. To issue
5. Expected return
6. Status

The agronomist plan remains immutable. An issued quantity may exceed the plan
when stock is sufficient. Expected return is calculated as
`max(issue quantity - planned quantity, 0)`. An issue above available stock is
rejected server-side.

## Receipt and Legacy Data

Ordinary receipts no longer require package metadata. Existing package
columns, functions and historic rows were not deleted. Historic package
metadata is ignored by the current UI and is not exposed to the Specialist.

Internal lot allocation remains deterministic and is an implementation detail.
The warehousekeeper enters only the final quantity.
