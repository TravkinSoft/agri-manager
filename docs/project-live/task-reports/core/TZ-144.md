## Result

- Создан единый TypeScript resolver `lib/warehouse/stock-unit-contract.ts` и server loader `lib/server/warehouse-stock-contract.ts`.
- Канонические единицы: `kg`, `l`, `pcs`; `g` и `ml` допускаются только через явную нормализацию.
- `mass_kg` для `l` остаётся `NULL`, если нет положительной плотности `kg/l`, источника, статуса `verified` и времени проверки.
- Пустая или неизвестная единица блокирует запись; fallback `quantity -> kg` удалён из новых writer paths.
- `batch_class` определяется до записи. `seed` не может стать `commodity`, а `material` не может быть замаскирован как `commodity`.
- Проверены 18 writer-сценариев из карты ТЗ №143; исправлены все 15 проблемных путей, остальные три уже наследуют доказанную identity или являются intrinsically kg.
- Новые balance/reconciliation views группируют по единице и классу партии; legacy unknown не суммируется с canonical остатком.
- Создана additive migration `20260713183038_warehouse_canonical_units_v2.sql`. Она сохраняет legacy columns, не содержит DML/backfill и не применялась к production.

## Writer paths

Общий resolver или его DB-enforced canonical contract используется для manual receipt/issue/return/adjustment/transfer/write-off, material request issue/return, operation reconciliation facts, weighbridge tickets/request conversion, product create/edit, batch creation, ledger posting, storno и processing movements.

Legacy authenticated RPC writers, которые не могут передать новый контракт, отозваны в migration до их отдельной V2-реализации. Это действует только после будущего apply migration.

## Schema and views

- `products`: nullable density evidence fields.
- `inventory_transactions`, `stock_ledger_entries`, `ticket_lines`, `inventory_batches`, `field_material_consumptions`: universal quantity/uom, optional mass/density snapshots, class and contract version where required.
- DB validator/triggers enforce canonical unit/class and exact ticket/ledger inheritance.
- `v_stock_movements_canonical`, `v_stock_balance_canonical`, `v_stock_balance_identity`, `v_stock_balance_reconciliation` are unit-aware.
- Three-argument balance helper blocks ambiguous multi-unit results; four-argument helper requires a requested unit.
