## Root cause

`/api/warehouses/balances` embedded `varieties:variety_id` and
`reproductions:reproduction_id` while reading `stock_ledger_entries`.
The scalar legacy identity columns still exist in the QA schema, but their
foreign-key relationships were deliberately removed. PostgREST therefore
could not resolve either embed from its relationship cache and rejected the
whole balance query before RLS-visible ledger rows could be returned.

The remaining embeds were checked against the live QA schema. `warehouse_id`
and `product_id` still have valid foreign keys; no other removed relationship
is used by the route.

## Fix

The invalid variety and reproduction embeds were removed from the ledger
select. The route keeps the current warehouse identity contract and resolves
optional variety/reproduction labels through two explicit, batched reads from
`varieties` and `seed_reproductions` using the same request-scoped user client.

Every data read uses the incoming Bearer JWT, RLS and the exact company id
resolved by the server ACL. Ledger, variety and reproduction errors return an
HTTP error response; the route never converts an upstream failure into a
successful empty balance list.

No service-role client was added or used. No schema, migration, production
connection or ERP write was performed.
