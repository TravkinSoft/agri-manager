## Result

The weighbridge workspace now opens directly on `Tickets` and `Processing`. Shift management is kept in a compact menu, while the weighman navigation contains only Weighbridge, Machines, Containers and Ledger.

For harvest intake, the weighman selects the field, an allocation only when the field has several crop-structure lines, the destination, driver, vehicle and gross weight. The server resolves the active-season harvest operation and operation line from the selected company, field and crop-structure allocation. Client-supplied harvest operation IDs are ignored. Missing or ambiguous harvest operations block ticket creation with a plain-language message.

Warehouse and processing destinations are company-scoped. A finalized processing-directed ticket appears in the embedded processing queue. The existing transformation lifecycle records one input, one output and explicit loss, is idempotent and keeps traceability to the source ticket without adding processed output to field yield.
