## Root cause

The Assistant QA branch did not contain a global pesticide snapshot:

- `public.products` contained only the three QA ERP products and zero global pesticides;
- `global_product_aliases` contained only five QA reference aliases;
- `glbd_components` contained 21 draft rows, all hidden from the QA JWT by its approved-only policy;
- component aliases, component sources and product-component links required by A110 were empty;
- `glbd_component_sources` also lacked an `authenticated` SELECT grant.

Real QA User A JWT reads therefore returned zero GLBD products, zero visible components and zero product-component links. This was primarily missing branch data, with a secondary rights mismatch; it was not an A110 table-name bug.

## Reproducible snapshot

`scripts/qa/sync-assistant-glbd-snapshot.mjs` builds a branch-only package from frozen, hash-verified TZ-196/TZ-197 catalog evidence. It reconstructs the approved TZ-197 post-apply state without opening a production runtime connection.

The generated package is stored outside Git under `audit-output/TZ-198/`. Every SQL file contains fail-closed ground-truth checks for:

- the Assistant memory branch marker;
- QA User A and its exact agronomist profile;

The package creates a dedicated `assistant_glbd_*` read surface. The loader closes all grants, reloads data in guarded chunks and publishes access only after the final count/safety transaction passes. No company product, field, warehouse, operation, user, stock or other company-scoped row is copied.

## Access model

- RLS is enabled on all nine snapshot tables.
- `authenticated` has SELECT only; INSERT, UPDATE and DELETE grants are absent.
- `anon` has no privileges.
- `assistant_glbd_search_surface` is `security_invoker` and exposes only the filtered snapshot.
- The runtime uses QA User A JWT and the branch anon key. No service-role key is used.
- The branch sync is an administrative test-fixture operation, not a runtime credential path and not a migration.
