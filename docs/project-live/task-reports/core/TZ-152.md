## Search map

The existing path was extended rather than duplicated:

`search text` -> `GET /api/global-admin/catalog/[entity]` -> `glbd_components + glbd_component_aliases batch reads` -> `canonical component_id dedupe/conflict check` -> `GlobalCatalogManager`.

Covered read surfaces:

- Global Admin active ingredient catalog;
- Global Admin pesticide, fertilizer and growth-regulator search;
- component chips in product composition;
- active-ingredient remote options, with canonical legacy IDs preserved;
- Knowledge Intake resolver and catalog options.

The company `/references` text-only agrochemistry field remains unchanged because it does not use the normalized component model. Assistant-owned code is unchanged.

## Implemented contract

- Search uses `canonical_name`, `name_ru`, `name_en`, `alias_text` and `normalized_text`.
- Normalization ignores case, extra spaces, punctuation, ordinary/long hyphens and `ё/е` differences.
- A component is returned once by canonical GLBD ID even when several names match.
- An exact alias mapped to several components returns a clarification payload; no random winner is selected.
- Product links and concentrations remain in the existing `product_active_ingredients` contract.
- Product composition components open one shared component card rather than a copied product-specific component.
- Component sources are queried only for the opened component card, in one bounded request. Lists, filters and selects never load all sources.
- Only active, non-archived components are available to the card. `needs_source` rows are filtered server-side and again in the display mapper.
- Source types and claim scopes are localized; internal status, UUID, normalized key and confidence are not rendered.
- Source links accept only HTTP(S), open in a separate tab and retain the exact verified URL.
- A component without sources shows: `Подтверждённые источники пока не добавлены.`
