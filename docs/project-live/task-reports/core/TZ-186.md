# TZ-186 - Load Core preview data through user JWT and RLS

DATE: `2026-07-17`
STATUS: `DONE_WITH_AUTH_RETEST_GATE`
CORE_BRANCH: `copilot-v1`
START_COMMIT: `c962d338b18e5dcb1d64875fb5747650f19d6aa6`
TEST_BRANCH_REF: `gsglkmudcwkdetqtocae`

## Root cause

Four read paths used `getServiceClient()` even though the Assistant preview is
intentionally configured without a service-role key:

- crop-structure bootstrap;
- warehouse list;
- warehouse product list;
- operation-line details.

Warehouse balances were also read directly in the browser from stock-balance
views. Those views are not marked `security_invoker` in the QA branch, so the
read path could not be accepted as a tenant-isolated user-RLS contract.

The warehouse page additionally contained a literal mojibake translation for
the read-only badge.

## Fix

`getUserScopedClientFromRequest()` now creates a request-scoped Supabase client
from the incoming Bearer JWT plus the public anon/publishable key. GET handlers
use this client, the existing actor/company resolver and RLS. Service-role
credentials are neither required nor sent to the browser.

Warehouse balances now load through `/api/warehouses/balances`. The endpoint
queries `stock_ledger_entries` under the signed-in user's JWT, applies the exact
resolved `company_id`, resolves only RLS-visible identity rows and aggregates
signed IN/OUT quantities. Existing write handlers were deliberately left out
of scope and were not invoked.

The corrupted RU/KZ badge text was replaced with valid UTF-8. A reusable
functional smoke was added at `scripts/qa/smoke-core-preview-data.ts`; it rejects
the production app and production Supabase ref, requires the exact QA branch,
performs no writes, checks non-empty data and asserts cross-company denial.

The local app was started with the exact QA Supabase URL and publishable key,
with `SUPABASE_SERVICE_ROLE_KEY` explicitly absent. All four protected GET
routes returned `401 Missing authorization token` without the former service
credential error when called without JWT. This proves the safe auth guard and
that the route bootstrap no longer requires service credentials.

Full signed-user functional smoke remains for A108 retest because neither the
in-app browser nor the available Chrome session had a QA login, and TZ-176
intentionally did not persist QA JWTs or passwords. No token was minted through
service credentials and no auth or ERP record was changed to bypass that gate.
