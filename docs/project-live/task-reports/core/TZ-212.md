## Result

The warehouse workspace now presents every warehouse as one clickable card, keeps receipt creation as a global action and opens the current aggregated balance, recent movements, receipts and requests in the warehouse dialog. Current stock is grouped by warehouse, canonical catalog identity and unit. Lots remain visible only in the stock-detail dialog, so multiple receipts do not create duplicate material rows.

Warehouse-to-warehouse transfers are server-timestamped and atomic: one idempotent RPC writes linked ledger `OUT` and `IN` rows, protects reservations and rejects over-transfer. Destination is chosen first, the source is fixed, only available source materials can be selected and the unit is derived from the balance.

Inventory is a separate `/warehouses/inventory` workflow. Starting it stores a balance snapshot and locks warehouse movements; warehouse staff can save and resume actual counts. Completion writes only the required ledger adjustments, records the completed document and exposes read-only history.

The receipt form uses supplier and material search, removes packaging fields, calls the receipt RPC without a client operation timestamp and names the traceability field `Партия / серия`.
