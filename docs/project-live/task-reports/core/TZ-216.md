# TZ-216 - Weighbridge V1.3

Date: 2026-07-22

Branch: `copilot-v1`

Status: `DONE_WITH_EVIDENCE_LIMITATION`

## Result

Weighbridge V1.3 now has one quantity source per movement. A weighed supplier receipt contains one kg item and converts final net weight into canonical warehouse quantity. An invoice receipt supports multiple lines with catalog units and a destination warehouse per line. Internal transfers reject identical warehouses on the server, preserve the existing manual transfer lifecycle and expose a weighed mode.

The first authenticated weighted-supply UI finalization exposed a schema-contract defect: the canonical unit trigger had copied gross weight into `ticket_lines.mass_kg`, while finalization replaced only `quantity` with net weight. The session finalizer now updates `quantity`, `net_line_weight_kg` and `mass_kg` together before the atomic ledger finalizer runs.

## Movement contracts

- Weighted supplier: one item, one destination, fixed `kg`, no manual quantity, no line warehouse, optional company driver and vehicle.
- Weighted catalog: grain, harvest, seed/planting material and confirmed dry bulk kg goods only. Pesticides, liquid fertilizer/additives, fuel, machinery and piece goods are rejected by both UI filtering and server validation.
- Invoice supplier: multi-line document; manual quantity, catalog `stock_unit`, line-level warehouse and no global destination. The atomic receipt RPC is idempotent.
- Internal transfer: destination excludes source in UI and exact server equality is rejected without ledger movement. Manual mode uses the existing transfer lifecycle; weighed mode uses net kg.
- Field issue: fuel and liquid pesticide/additive categories are removed; the category controls no longer overlap.
- Supplier transport is optional. Internal transport remains required.
- Harvest operation/operation-line auto-linking and the impurity-removal scenario from TZ-213/TZ-214 are unchanged.

## Counterparties

Company Admin has a `Покупатели` reference view. Global and local counterparties share one identity with `supplier` and `buyer` roles. Search covers legal name, short name, tax ID and aliases. The database preserves unique `country_code + tax_id`; adding buyer to existing SWISSGROW did not create another organization.

## Inventory approval

- Company Admin starts an inventory, selects a warehouse and assigns a Warehousekeeper or Weighman.
- The assignee records actual quantities and submits the document but cannot approve, reject or create ledger adjustments.
- Company Admin can approve or reject with a required rejection comment. Ledger adjustments are created only during approval.
- The warehouse remains movement-locked from inventory start through approval, rejection or cancellation.
- Warehousekeeper E2E: 16 lines, one positive difference, zero ledger rows before approval and one adjustment after admin approval.
- Weighman E2E: three grain lines, zero difference, zero ledger rows before and after admin approval.
- Rejection E2E: empty comment rejected, admin rejection accepted, ledger unchanged and warehouse remained locked until admin cancellation.
