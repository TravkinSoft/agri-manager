## Root cause and correction

Migration `20260716114950_catalog_rls_function_security_hardening.sql` assumed
schema `private` already existed. The TZ-167 branch concealed that dependency
because branch-only Assistant Memory V1 had created the schema. Production has
no Assistant Memory objects and no `private`, so TZ-168 stopped atomically with
SQLSTATE `3F000`.

The same unapplied migration version now creates and owns `private` itself,
revokes schema access from `PUBLIC` and `anon`, grants only required `USAGE`,
and creates all private helper functions before policies reference them. A
second migration was not created. No business DML or destructive legacy-table
operation was added.
