production deployment and `master` were not changed.

## Root Causes

- Calendar dates were serialized through UTC timestamps instead of a date-only
  contract.
- Analytics lacked a single current-season choice and treated query failures as
  valid zero values.
- Operation completion and warehouse request finalization could diverge.
- Field history used incomplete planned data instead of reconciled material
  facts.
- Physical preparation and issue relied too heavily on client validation.
- Reservation math clamped negative availability and obscured deficits.
- Target, crop identity and machinery selectors allowed unsafe implicit choices.
- Material selectors did not consistently use Catalog Identity, and material
  changes retained an incompatible rate.
- Notification switches had no persisted, user-scoped server contract.
- Weighbridge validation happened too late and ambiguous harvest identity could
  be selected implicitly.
- Several pages exposed raw enums, technical errors or non-localized dates.

  conversion.

### Crop identity and weighbridge

- New harvest-derived documents require crop, variety and reproduction.
- Existing incomplete rows are not guessed or rewritten; six rows are marked
  for review and now show a clear warning.

  values are valid.
- Hidden duplicate form markup was removed and double submit is blocked.

  `1.35` measured browser viewports in the available scaled 1366-wide runtime.

### Reconciliation and field history

- QA request `WR-2026-000035` and its operation both finish as `closed`.

  `WR-2026-000035`, actual rate `1 л/га` and reconciled status.

### Warehouse and ledger

- Prepare and issue stages validate physical availability on the server.
- Deficit responses identify requested, on-hand, reserved, available and
  missing quantities.
- Availability is no longer clamped to zero.
- Canonical signs are receipt/return `positive`, issue/loss `negative`;
  transfer remains paired source-negative/destination-positive.
- Reservation trace includes request, operation, field, material and status.
- Repeat reservation/finalization is guarded.

### Planning and catalog

- Ambiguous extra targets are created empty; incomplete and duplicate targets
  are rejected by API validation.
- Spraying no longer accepts mower equipment; compatibility is shared by UI and
  API paths.
- Catalog Identity deduplication is used in operation, crop-care, warehouse and
  weighbridge material selectors.
- Company override remains preferred over a verified global identity.
- Review candidates `-НОВАКРИД, сух.п.` and `2020Ел` were not auto-corrected.
- Material, rate-unit or stock-unit changes reset the rate and request explicit
  re-entry; no kg/l conversion is guessed.

### Settings and presentation

  API upsert with optimistic rollback and feedback.
- Browser refresh preserved the changed value; the temporary verification row
  was removed and the exact pre-test state restored.
- Operation form uses `Норма расхода рабочей жидкости`; materials, material
  total, water, concentration and final solution follow the approved order.
- Dashboard and analytics operation/material enums and date-only values are
  localized.
- Comboboxes and switches have accessible labels; the operation footer no
  longer covers content.
- Raw service-role/secret errors are replaced by a user-safe Copilot message.
