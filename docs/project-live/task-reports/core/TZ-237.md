## Result

The existing Global Admin pesticide catalog now opens a compact human
agronomic card backed by one dedicated read model. The primary surface is one
two-column table followed by a short description. Empty rows, technical
readiness fields, sources, UUIDs, advertising blocks, decorative panels and
duplicate information are not rendered.

All `852` pesticide cards built successfully. The read model preserves
canonical links when available and shows safe raw crop, target and rate values
instead of false empty states. It does not guess missing rates, units, targets
or automatic-recommendation readiness.

## Root Causes

- The former UI prioritized technical catalog metadata over agronomic usage.
- Useful component and usage-rule data lived in separate tables without one
  human read model.
- Missing canonical relations hid valid raw crop and target text.
- Different crop-specific values were flattened or omitted.
- Technical placeholder descriptions were treated as user content.
- Crop parser fragments could appear as independent cultures.

## Implementation

- Added `lib/glbd/human-pesticide-card.ts` as the deterministic aggregation and
  display contract.
- Added authenticated Global Admin endpoint
  `/api/global-admin/pesticide-card/[id]`.
- Updated the existing pesticide catalog dialog and manager; no new page or
  catalog was created.
- Added exact mapping review/apply, coverage and read-model QA scripts.
- Added QA-only SELECT policies for Global Admin review of component rows.

The endpoint reads `products`, `glbd_product_components`,
`glbd_product_usage_rules` and `global_product_aliases` through the signed-in
user JWT and RLS. No service-role credential is used by the client or route.
