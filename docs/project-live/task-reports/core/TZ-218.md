## Result

Agronomist and Specialist now use one shared operation presentation model. It
returns the concrete work title, crop identity, immutable plan, cumulative
fact, remaining area or over-plan deviation, display status, responsible
person, saved machinery and type-specific details.

The specialist task list is compact and opens one full dialog. The agronomist
operation list has separate plan, progress, remaining/deviation, responsible
and status columns; clicking a row opens the full operation sheet. Empty
materials, warehouse request and optional plan fields are omitted.

Legacy machine/equipment IDs are hydrated through the authenticated,
company-context company-assets endpoint instead of invalid PostgREST relation
embeds. Legacy operation codes are presented with canonical Russian labels.

## Progress and completion contract

- `planned_area_ha` remains the agronomist plan.
- Every shift stores a delta and updates cumulative actual, remaining area and
  percentage atomically.
- Progress and finish commands require a confirmation dialog and idempotency
  key.
- Exact-plan finish completes atomically with field history.
- Under-plan and over-plan finish create a pending completion request with a
  mandatory reason.
- Agronomist approval rechecks dependencies and writes final history once.
- Agronomist rejection requires a comment and returns the operation to the
  specialist without editing the reported fact in place.

The test-branch E2E passed:

- soil operation: plan `80 ha`, depth `12 cm`, progress `34 ha`, remaining
  `46 ha`, real machine/equipment and comment round-trip;
- under plan: `34 + 44 = 78 ha`, deviation `-2 ha`, approval and one history
  row;
- over plan: `82 / 80 ha = 102.5%`, rejection, resubmission, approval and one
  history row;
- repeated progress, finish and approval commands created no duplicates;
- foreign company visibility was `0`, cross-company create returned `403`.

## Materials

Planning now searches the authenticated global and company catalog including
aliases and does not depend on warehouse stock.

The mixed sowing test stored seed, fertilizer and pesticide in one operation.
Only fertilizer and pesticide produced warehouse request lines; seed remained
linked to `weighbridge_issue_to_field`. The multi-field spraying test stored
two operation lines, fertilizer and pesticide request lines, and `200 l/ha`
solution data.

Material reconciliation, warehouse ledger rules and the open weighbridge guard
were not changed. A new seed weighbridge ticket was not created in this task;
the existing operation linkage contract was preserved and checked by schema
and route regression.
