# TF Assist harvest v1 — контракт границ

## Доступ и включение

Новый endpoint `POST /api/tf-assist/query` работает только вне `VERCEL_ENV=production` и с QA Supabase `gsglkmudcwkdetqtocae`: по явному `TF_ASSIST_HARVEST_V1=1` либо автоматически на утверждённой Preview-ветке `codex/tf-assist-harvest-foundation-20260913`. Значение `TF_ASSIST_HARVEST_V1=0` всегда выключает функцию. Общий gate из `preview-gate.js` используется сервером и Next build для UI; Production UI принудительно выключен даже при ошибочном флаге. Другие ветки автоматически не включаются. Наличие флагов не расширяет права: нужен active canonical Global Admin без legacy alias/impersonation и явно выбранный серверный `contextCompanyId`.

Тело запроса строго проверяется Zod: `companyId`, `message`, необязательные `seasonId`, `sourceId`, `harvestedHa`, `remainingHa`. Неизвестные ключи отвергаются. Лимиты: 2000 символов вопроса, 12000 байт тела, один одновременный запрос на user/company в экземпляре сервера; это локальный ограничитель, не распределённая квота. Роль/компания проверяются без actor cache до чтения и перед возвратом. Смена пользователя/компании отменяет ответ. Ответы имеют private/no-store и Vary Authorization/Cookie.

`GET /api/tf-assist/health` — только булевы признаки enabled/qaBound/uiEnabled/aiConfigured/sourceCredentialConfigured/productionLocked. Не возвращает секреты, имена пользователей, выбранную компанию или строки БД. Позволяет проверить удалённую конфигурацию без вызова модели.

## Read-only capability

`contracts.ts` содержит исчерпывающие таблицы/проекции, `read-only.ts` строит GET `/rest/v1/<allowlisted table>` на фиксированном QA origin. Нет Supabase mutation client, SQL, RPC, URL аргумента, навигации по model tool calls. Redirect запрещён. Каждая таблица ограничена company_id; crops/varieties/seed_reproductions допускают только текущую компанию и глобальные строки с company_id=null. Возвращённая company_id проверяется повторно, лишние колонки удаляются.

Для PTC/fleet SELECT у authenticated отсутствует, поэтому используется существующий server service credential в узком GET-only адаптере. Это не RLS-ограниченная DB credential: защита от записей обеспечена фиксированным адаптером и отсутствием пути к нему у модели. Auth использует существующий `getServerActorFromSession` с фиксированными RPC разрешения сессии; эти RPC не выдаются модели. Никаких новых DB ролей/GRANT/миграций в этом изменении.

Пагинация: стабильный UUID keyset, максимум 500 строк/страницу и 10000 строк/источник, exact remaining count; серверный cap меньшего размера учитывается. Дубли/неправильный порядок, чужой tenant, отсутствие count, timeout, ошибка или лимит превращают источник в unavailable/truncated с удалением частичного результата. Ошибка не равна нулю. Общий бюджет reader 35 секунд. REST-чтения не атомарны: ответ указывает read interval и digest каждого источника, без обещания транзакционного снимка.

## Модель и доказательства

`planner.ts` — отдельный Responses adapter с injectable transport для mock-тестов. Использует существующие OPENAI_API_KEY и OPENAI_ASSISTANT_MODEL (default соответствует текущему project default gpt-5.4-mini). В API передаются только системный контракт и текущий вопрос; `store=false`, tools отсутствуют. История чата, данные БД, компания и идентификаторы источников модели не передаются. Строгая схема ответа разрешает только intent и asksWrite. Числа, SQL, tool calls, лишние поля, отказ модели и неподдерживаемая тема не исполняются. Server veto команд записи применяется до вызова модели.

При недоступном ключе/сетевой ошибке остаются ограниченные локальные правила разбора известных вопросов с явным предупреждением. Это независимый режим чтения, а не доказательство работоспособности OpenAI. Успешный mock не заменяет реальный remote model gate.

Ссылка на проверенную спецификацию: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). Строгая схема не является заменой серверной авторизации и проверки чисел.

Каждая метрика содержит kind (fact/calculation/forecast), формулу при необходимости и evidence (таблица, ID, статус, дата, исходное значение). UI выводит текст как React text nodes, не HTML/Markdown из БД. Каждый запрос логирует только request/user/company IDs, intent, источники/статусы/digests и время. Raw prompt, ответы модели, строки БД, контакты и ключи не логируются.

## Урожай, склад, примесь

- Масса хранится в расчёте целыми граммами; лишняя точность, null и unsafe integer отвергаются. Площадь — 1/10000 га. Прогноз массы по площади использует рациональное BigInt вычисление.
- Effective harvest = op_type harvest_incoming, status finalized, is_finalized=true, не voided, без replacement_ticket_id. Старый заменённый документ не суммируется с действующим исправлением. Open tickets считаются отдельно без добавления веса.
- Источник — crop_structure UUID с проверкой сезона/поля/культуры/сорта/репродукции, однозначным harvest_lot_batches/inventory linkage и ticket_lines. Имена не являются join keys; совпадающие названия/репродукции требуют выбора. Неопределённость и requires_review блокируют полную урожайность.
- Масса принятого урожая = accepted_weight_kg, fallback net_weight_kg; это урожай до **складской** примеси, не GROSS машины с тарой. Площадь структуры показывается отдельно и не подменяет фактически убранную площадь. Сообщённые пользователем гектары — допущение, не запись в ERP.
- Business date использует только два проецированных scalar paper_backfill поля, затем корень correction chain и канонические времена. Архивный источник доступен при явном сезоне. Запросы за день сейчас отклоняются с уточнением: v1 считает полный сезон, не молча подставляет его вместо дня.
- Чистая масса подтверждается для V2 proportional_members только при effective impurity ticket, совпадении суммы source/member allocations и отсутствии повторного покрытия batch. Один shared document не создаёт новую чистую смесь. V1 schema fallback явно означает отсутствие подтверждённого source clean total. Миграция не запускается.
- Покрытие общей примесью может быть частичным. Оформленная чистая масса показывается отдельно; полная чистая урожайность — только при полном согласованном покрытии. Источник без V2 измерений не получает выдуманный процент примеси. Границы прогноза берутся из наблюдаемых долей того же source; это сценарий, не статистический доверительный интервал.
- Склад: точные исходные batch IDs и parent lineage, конфликт/цикл блокирует итог. Signed ledger включает сторно, технические pools исключаются. Масса выводится только для kg. Сверка показывает разницу между effective receipt sum и net harvest ledger. Остаток по связанным движениям не равен доступному для отгрузки: резервы не вычитаются.
- PTC/repair — текущие состояния без угадывания рейса по времени/имени. ПТЦ cycle не считается взвешенным рейсом. Ответственный машины не подменяет исторического водителя. Текущее время в состоянии не объявляется доказанным простоем.

## Память и расширение

В первом срезе нет DB persistence памяти и нет переноса A108/A110. Клиент хранит до 10 ответов в состоянии компонента, привязанном к user/company; при смене scope всё очищается и поздние ответы игнорируются. Выбранный source перепроверяется на каждом запросе, новое явно названное поле отменяет старый focus. Живые факты всегда перечитываются.

Будущий persistent контракт должен иметь отдельные типы PersonalPreference(userId), CompanyAlias/Rule(companyId), SystemAgronomy(version), и никогда не сохранять numeric business facts как память. Директор/company admin/agronomist пока не включены. Ни один из этих будущих контрактов не требует текущей миграции.

## Сознательные границы первой основы

Дневной произвольный период, статистическая модель доверия, подтверждение чистоты вне проверенного shared-impurity V2, persistent memory/aliases, резервирование, полноценная диагностика простоев и самостоятельные агрономические рекомендации не выдаются как реализованные. В этих ситуациях ответ обозначает границу доказательства или просит точный источник. Перед реальным включением нужны remote env gate и положительная браузерная QA-сессия Global Admin; unit tests и отсутствие auth сами по себе этот gate не заменяют.
