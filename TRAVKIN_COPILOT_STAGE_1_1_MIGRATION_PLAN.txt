1) FILE-BY-FILE MIGRATION MATRIX
========================================================================

FILE: app/api/assistant/query/route.ts
Current role:
- HTTP entrypoint, runtimeContext/sessionState intake, response/debug payload.
Future role:
- Thin orchestration gateway with stable API contract.
What moves:
- No core reasoning logic.
What stays:
- Auth/actor/company checks, request validation, output contract, trace transport.
Risk:
- Debug monitor schema drift.
Rollback:
- Keep backward-compatible response fields; fallback by ASSISTANT_ENGINE_MODE=tool_first.

FILE: app/api/assistant/context/route.ts
Current role:
- Runtime context snapshot API.
Future role:
- Stable context snapshot provider for Context Collector.
What moves:
- Nothing semantic; only stricter context shape guarantees.
What stays:
- Company/page/season/entity extraction.
Risk:
- Context mismatch between API and engine if schema changes.
Rollback:
- Keep previous fields and add new fields as optional only.

FILE: lib/assistant/engine/runtime.ts
Current role:
- Runtime context helpers.
Future role:
- Canonical Context Collector normalization layer.
What moves:
- Context merge rules (user text > explicit entity > page hint > defaults) consolidated here.
What stays:
- Helper utilities and normalization.
Risk:
- Wrong context merge can lock intent to wrong module.
Rollback:
- Fallback to legacy context parser in query.ts by feature flag.

FILE: lib/assistant/engine/session-state.ts
Current role:
- Memory update from tool outputs.
Future role:
- Core conversation memory layer for follow-ups.
What moves:
- Strong memory keys: last_entity, last_field, last_warehouse, last_module, last_season, last_tool_source.
What stays:
- Lightweight session-level fact store.
Risk:
- Stale memory contaminates next answer.
Rollback:
- Thread-level memory reset and selective key disable.

FILE: lib/assistant/engine/query.ts
Current role:
- Main decision hub: router, fast-path, planner branch, legacy fallback, formatting branches.
Future role:
- Coordinator only: fast-path gate + planner-first dispatch + fallback control.
What moves:
- Hard intent/tool decision branches away from router-style logic toward planner policy.
What stays:
- Engine-mode switch, fast-path gating, final safety fallbacks.
Risk:
- Regression of currently working deterministic intents.
Rollback:
- Instant env rollback: ASSISTANT_ENGINE_MODE=tool_first.

FILE: lib/assistant/engine/router.ts
Current role:
- Rule-based fallbackIntent (regex + context).
Future role:
- Cheap pre-classifier and emergency fallback only.
What moves:
- Most semantic intent decisions to GPT planner.
What stays:
- Deterministic regex for obvious commands, emergency fallback for model/tool failure.
Risk:
- Losing fast deterministic behavior on trivial prompts.
Rollback:
- Keep fallbackIntent intact and callable; narrow hybrid domains if needed.

FILE: lib/assistant/engine/model-orchestrator.ts
Current role:
- Planner path with tool_choice=auto and tool loop.
Future role:
- Primary reasoning pipeline for semantic queries.
What moves:
- Intent/tool reasoning priority for non-deterministic questions.
What stays:
- Model fallback list, tool execution loop, usage metadata, llm diagnostics.
Risk:
- Latency and token-cost growth.
Rollback:
- Restrict planner domains using ASSISTANT_HYBRID_DOMAINS.

FILE: lib/assistant/engine/tool-schema.ts
Current role:
- Planner-visible tool schema and mapping.
Future role:
- Canonical model-facing tool contract.
What moves:
- Missing domain actions/tools (rotation/materials/driver-centric questions) into planner schema.
What stays:
- Mapping to existing assistant tools (no DB schema changes).
Risk:
- Wrong schema can force wrong tool calls.
Rollback:
- Versioned schema strategy (keep v1 mapping available).

FILE: lib/assistant/engine/tools.ts
Current role:
- Source-of-truth tool implementations (Supabase queries, RLS scope, logs).
Future role:
- Same role; data truth layer.
What moves:
- Nothing architectural from here.
What stays:
- SQL/query semantics, scope enforcement, rows_count/error logging.
Risk:
- Accidental behavior changes in critical tools.
Rollback:
- Preserve signatures; revert tool-only commits if needed.

FILE: lib/assistant/engine/navigation-policy.ts
Current role:
- Explicit-navigation detector and action allow/block.
Future role:
- Mandatory post-planner policy gate.
What moves:
- All final action filtering centralized here.
What stays:
- Explicit command requirement logic.
Risk:
- Overblocking legitimate navigation.
Rollback:
- Temporary relax through ASSISTANT_NAV_POLICY_STRICT=0.

FILE: lib/assistant/engine/response-validator.ts
Current role:
- Grounded answer validator (basic).
Future role:

What moves:
- Answer type validation and contradiction handling from scattered branches into validator layer.
What stays:
- Grounded/no-data normalization.

Rollback:
- Downgrade to basic validator mode (feature flag).

FILE: lib/assistant/openai.ts

========================================================================
2) STAGE 1.1 EXECUTION ORDER (UPDATED, NO CODE)
========================================================================

Step 1: Freeze contracts and telemetry
- Files: route.ts, types.ts, debug monitor, trace script.
- Goal: trace always includes model, decisionSource, answerSource, latency parts.

Step 2: Context Collector + Memory Layer
- Files: runtime.ts, session-state.ts, context route, query.ts (integration points only).
- Goal: follow-up stability:
  - "Что на поле 28?" -> "А материалы?" -> "А операции?" -> "А урожай?" -> same field context retained.
  - "А по складу?" -> "А последние движения?" -> same warehouse context retained.

Step 3: Shift reasoning priority
- Files: query.ts, model-orchestrator.ts, router.ts.
- Goal: semantic queries go planner-first; router becomes pre-classifier/fallback.

Step 4: Expand planner tool coverage
- Files: tool-schema.ts (+ mapping), tools.ts unchanged in signature.
- Goal: planner can choose correct tools for rotation/materials/driver cases.

Step 5: Enforce trust/safety gates
- Files: navigation-policy.ts, response-validator.ts.
- Goal: no fake navigation, no ungrounded ERP numbers.

Step 6: Controlled rollout and verification
- Files: trace/qa scripts.
- Goal: compare old vs hybrid, domain by domain.

5) ENV FLAGS FOR SAFE ROLLOUT/ROLLBACK
========================================================================

Primary mode switch:
- ASSISTANT_ENGINE_MODE=tool_first | hybrid | model_first

Domain rollout:
- ASSISTANT_HYBRID_DOMAINS=all or scoped list

Navigation guard:
- ASSISTANT_NAV_POLICY_STRICT=1 (recommended)

Fast rollback path:
1) Set ASSISTANT_ENGINE_MODE=tool_first
2) Keep API/debug contract unchanged
3) Re-run trace + QA matrix
